# dicodePing v2.0.6 — انتشار پایدار اتصال و سنجش شبکه

این نسخه پایداری اتصال، سرعت سنجش و سازگاری چهار پلتفرم Windows، Linux، macOS و Android را بهبود می‌دهد.

## تغییرات اصلی

- تست اصلی اتصال به `http://captive.apple.com/hotspot-detect.html` منتقل شد و endpointهای مستقل دیگر به‌عنوان fallback باقی ماندند.
- پینگ واقعی پروکسی و دریافت IP/لوکیشن هم‌زمان اجرا می‌شوند؛ نتیجه‌ها تدریجی و بدون قفل‌کردن رابط نمایش داده می‌شوند.
- endpointهای مرده ابتدا با TCP سریع حذف می‌شوند و فقط گزینه‌های زنده وارد پروب سنگین Xray می‌شوند.
- DNS هر سرور یک‌بار resolve و میان مسیر پینگ و geo به اشتراک گذاشته می‌شود؛ Happy Eyeballs برای IPv4/IPv6 فعال است.
- زنجیره CA قابل‌حمل با `certifi` داخل بسته‌های دسکتاپ قرار گرفت و خطای `CERTIFICATE_VERIFY_FAILED` در macOS بدون غیرفعال‌کردن TLS رفع شد.
- پروب‌های HTTPS داخلی Xray/SOCKS نیز اکنون زنجیره گواهی و hostname را با همان CA معتبر بررسی می‌کنند؛ مسیر قدیمی `CERT_NONE` حذف شد.
- مسیر VPN اندروید اصلاح شد تا پردازش برنامه و هسته Xray داخل VPN خودش حلقه نشوند.
- پاک‌سازی خودکار `font_certs.xml` و منابع قدیمی downloadable-font اضافه شد تا Android lint در workspaceهای قدیمی هم پایدار بماند.
- APK یونورسال شامل `arm64-v8a`، `armeabi-v7a` و `x86_64` است.
- بسته‌ها همچنان Xray، Aether و Usque را همراه دارند و smoke test واقعی روی هر چهار خروجی اجرا می‌شود.
- ناشر ویندوز اکنون فقط فایل‌های ثبت‌شده در manifest دارای SHA-256 را stage می‌کند؛ فایل‌ها و تست‌های قدیمی باقی‌مانده از Extractهای قبلی نادیده گرفته می‌شوند و وارد Commit یا Pytest انتشار نمی‌شوند.
- CodeQL اندروید اکنون فقط bytecode جاوا/کاتلین را تحلیل می‌کند و دیگر به helperهای runtime تولیدنشده وابسته نیست؛ Build واقعی APK همچنان Aether و Usque را برای هر سه ABI می‌سازد و بررسی می‌کند.
- پیش از Build اندروید در CodeQL، فونت‌های واقعی و integrity-checked وزیرمتن برای وزن‌های Regular، Medium و Bold ساخته و وجود هر سه فایل کنترل می‌شود؛ بنابراین AAPT دیگر به resource گمشده ارجاع نمی‌دهد و فونت از صورت مسئله حذف نشده است.
- ناشر پایدار اجرای دقیق CI و CodeQL را بر اساس SHA همان PR دنبال می‌کند، Mergeهای موقتاً ناموفق را با تأیید وضعیت واقعی Retry می‌کند و در شکست Build، لاگ مرحله خراب را چاپ و ذخیره می‌کند.
- صفحه Release فقط پس از تأیید Stable/Latest بودن، تطابق Tag با Commit و وجود همه خروجی‌های لازم باز می‌شود.
- اعتبارسنجی نهایی PR اکنون Check Runها و commit statusها را مستقیماً برای SHA تغییرناپذیر همان Head از GitHub REST API می‌خواند؛ شکست قدیمیِ باقی‌مانده از force-push قبلی نمی‌تواند نتیجه Commit جدید را خراب کند، اما هر شکست واقعی روی SHA جاری همچنان انتشار را متوقف می‌کند.
- پیش از Push، ناشر وضعیت CodeQL Default Setup مخزن را از API رسمی GitHub بررسی می‌کند و در صورت فعال‌بودن، آن را به `not-configured` تغییر می‌دهد تا فقط Workflow پیشرفته و واقعی `.github/workflows/codeql.yml` اجرا شود؛ هیچ شکست CodeQL نادیده گرفته نمی‌شود و تضاد دو پیکربندی هم‌زمان از ریشه حذف می‌شود.
- پیش از Commit، پایان خط‌ها، فاصله‌های انتهایی و سطرهای خالی انتهای فایل‌ها به‌صورت قطعی normalize و سپس با `git diff --check` کنترل می‌شوند.

- رفع شکست CI لینوکس در تست‌های اتصال: importهای `PySide6.QtGui` و EGL از مسیر شبکه جدا و فقط هنگام نصب patch رابط کاربری بارگذاری می‌شوند؛ runner نیز حداقل runtime لازم `libegl1/libgl1` را نصب می‌کند.
- ناشر ویندوز دیگر کل درخت Git را حذف و دوباره اضافه نمی‌کند؛ فایل‌های خارج از manifest حذف می‌شوند اما mode فایل‌های موجود حفظ می‌شود، بنابراین Commit انتشار از صدها تغییر permission غیرضروری پاک می‌ماند.

## انتشار و کنترل کیفیت
