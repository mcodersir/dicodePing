# dicodePing v1.8.0-rc.4 — Reliable Connection & Clear Latency

## فارسی

RC4 چهار مشکل گزارش‌شده را مستقیماً رفع می‌کند:

- ستون مبهم Ping به دو معیار مستقل تبدیل شد: `ICMP` برای RTT اندپوینت و
  `Xray HTTP` برای زمان عبور یک درخواست HTTP واقعی از همان کانفیگ. انتخاب
  خودکار فقط به معیار دوم اعتماد می‌کند.
- اتصال Xray پیش از اعلام موفقیت، ابتدا کانفیگ و ترافیک HTTP را از یک SOCKS
  داخلی اختصاصی و سپس مسیر سراسری TUN را بررسی می‌کند. پورت‌های validation
  و API رزرو و در تمام مسیرهای خطا/توقف آزاد می‌شوند.
- منوی انگلیسی سمت چپ و منوی فارسی سمت راست قرار می‌گیرد. تغییر زبان همان
  لحظه و بدون Restart کردن Process انجام می‌شود.
- با فعال‌کردن Aether یا WARP، صفحه Home به کنترل اختصاصی همان هسته تبدیل
  می‌شود و دکمه روشن «اتصال با Aether/WARP» نمایش داده می‌شود.

بهبودهای پایداری:

- تست انتخابی سرور دیگر TCP-only را سالم ثبت نمی‌کند.
- Aether از حالت واقعی Ironclad استفاده می‌کند.
- Aether و Usque در صورت بسته‌بودن QUIC/MASQUE به‌صورت خودکار HTTP/2 را
  امتحان می‌کنند.
- مقدار آمار پشتیبانی‌نشده در هسته‌های جایگزین دیگر باعث خطای مانیتور اتصال
  نمی‌شود.
- Scanner همچنان بعد از رسیدن به ۵ سرور دارای HTTP موفق متوقف می‌شود تا
  صدها کانفیگ غیرضروری روی دستگاه ذخیره نشود.

تست واقعی این تغییر:

- ۱۵۷ تست Python، quality gate، کنترل نسخه و Android project validation سبز.
- Xray `26.7.11` با یک کانفیگ زنده HTTP موفق عبور داد و Process یتیم باقی
  نگذاشت.
- Scanner از ۲۰ کانال ۴۲ کانفیگ یکتا گرفت و در ۲۳ ثانیه ۵ سرور سالم واقعی
  پیدا کرد؛ Process یتیم: صفر.
- Aether و Usque نصب، self-test، listener، fallback و cleanup واقعی شدند.
  شبکه اجرای محلی هر دو مسیر QUIC و HTTP/2 Cloudflare را timeout کرد؛ بنابراین
  برنامه این وضعیت را Connected جعلی نمایش نمی‌دهد.

محدودیت‌های صادقانه:

- Android در RC4 فقط Xray داخلی را برای اتصال فعال می‌کند. Aether، WARP و
  Psiphon تا وجود Library داخلی هم‌پکیج غیرفعال‌اند.
- Psiphon فقط در Build دارای تنظیمات توزیع مجاز فعال می‌شود. نبود Secretها
  مانع Build یا Release نیست و Config ساختگی تولید نمی‌شود.
- Manifest هسته‌ها SHA-256 verified است. اگر کلید امضای CI موجود نباشد،
  ادعای Signed Manifest نمایش داده نمی‌شود.

## English

RC4 directly fixes the four reported problems:

- The ambiguous Ping column now shows separate endpoint `ICMP` RTT and
  verified `Xray HTTP` latency. Automatic selection trusts only the latter.
- Xray validates the selected outbound through a private SOCKS inbound before
  validating system-wide TUN routing. Validation/API ports are centrally
  reserved and released on every stop and failure path.
- The English rail is on the left and Persian rail is on the right. Locale
  changes apply immediately without restarting the process.
- Activating Aether or WARP transforms Home into a dedicated core control
  screen with an explicit Connect/Disconnect action.

Reliability improvements:

- A selected-server refresh can no longer save a TCP-only result as healthy.
- Aether uses its real Ironclad mode.
- Aether and Usque automatically fall back from filtered QUIC/MASQUE to HTTP/2.
- Explicit unsupported counters no longer crash alternative-core monitoring.
- Scanner stops after five verified servers instead of filling devices with
  hundreds of unnecessary configurations.

Validation performed:

- 157 Python tests, version validation, quality gate and Android project
  validation passed.
- Xray `26.7.11` carried live HTTP through a saved configuration with zero
  orphan processes.
- Scanner collected 42 unique configs from 20 channels and found five
  HTTP-verified servers in 23 seconds, leaving zero orphan processes.
- Aether and Usque install/self-test, listener, fallback and cleanup paths were
  exercised. The current test network timed out both Cloudflare QUIC and HTTP/2
  paths, and RC4 correctly refused to display a fake Connected state.

Honest limitations:

- Android enables only the built-in Xray transport in RC4. Aether, WARP and
  Psiphon remain disabled until same-package libraries are available.
- Psiphon is enabled only when authorized distribution settings are supplied
  to CI. Missing secrets do not fail the build and no fabricated config exists.
- Core manifests are SHA-256 verified. The UI does not claim a signed manifest
  when the CI signing key is absent.
