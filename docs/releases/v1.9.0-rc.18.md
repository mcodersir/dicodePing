# dicodePing v1.9.0-rc.18

RC18 restores mandatory full-device Xray TUN routing on Windows, Linux and macOS.

## Desktop Xray TUN correction

- Uses an Xray `tun` inbound as the primary desktop connection path; System Proxy is not used as a substitute.
- Installs IPv4 and IPv6 default routes through Xray with platform-specific TUN settings.
- Prevents outbound routing loops with automatic outbound-interface selection, source binding and temporary direct host routes for the selected server.
- Packages and validates `wintun.dll` on Windows and requests UAC elevation.
- Requests Linux TUN privileges through PolicyKit while preserving the user's profile and graphical-session environment.
- Uses a valid `utunN` interface and the native administrator prompt on macOS.
- Validates the selected Xray outbound through a private loopback SOCKS listener, then validates ordinary no-proxy traffic through the system TUN route.
- Does not report a connected state unless both the server and the full-device route carry real HTTP traffic.
- Cleans Xray, temporary host routes, runtime state and the TUN interface on disconnect.
- Retains one-time stale System Proxy recovery only for users upgrading from the earlier incorrect RC18 package.

## Existing RC17 improvements retained

- Persistent scanner SUB storage with location metadata.
- Human-readable server validity and configuration-security estimate.
- Optimized and professional resource modes.
- Aether and WARP/Usque integration across desktop and Android.

The release workflow builds Windows, Linux, macOS and Android artifacts, then publishes checksums, release notes, source and SBOM files.
