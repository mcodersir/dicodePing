# dicodePing v1.9.0-rc.13

## فارسی

RC13 مسیر دریافت کانال‌های تلگرام در Android را از نو اصلاح می‌کند. علت خطای گزارش‌شده این بود که خود برنامه برای جلوگیری از حلقه VPN از `VpnService` مستثنا بود؛ در نتیجه درخواست اسکنر از اینترنت مستقیم و IPv6 فیزیکی دستگاه خارج می‌شد، نه از Xray متصل‌شده.

| بخش | تغییر |
|---|---|
| مسیر Android | یک ورودی SOCKS5 محلی داخل همان Xray فعال ساخته می‌شود و تمام درخواست‌های `t.me` اسکنر مستقیماً وارد آن می‌شوند |
| DNS | نام `t.me` در مسیر پراکسی حل می‌شود و دیگر DNS یا IPv6 فیزیکی گوشی برای اسکن استفاده نمی‌شود |
| الگوریتم دریافت | مانند DicodeConfigChecker، هر کانال مستقل بررسی می‌شود؛ خرابی چند کانال اول کل اسکن را متوقف نمی‌کند |
| منبع | فقط `https://t.me/s/<channel>`؛ هیچ درخواست فعالی به `telegram.me` وجود ندارد |
| سرعت | ۸ Worker محدود، Keep-Alive، لغو واقعی درخواست‌ها و پایان زودهنگام پس از رسیدن به هدف |
| Progress | پیشرفت بر اساس ۷۰٪ کانال‌های پردازش‌شده و ۳۰٪ تعداد کانفیگ هدف محاسبه می‌شود و عقب نمی‌رود |
| خروجی | کانفیگ‌های خام اتمیک ذخیره می‌شوند، VPN اولیه قطع می‌شود و سپس تست واقعی Xray انجام می‌شود |

### روند اسکن

1. تأیید اتصال VPN از صفحه خانه
2. بازکردن مسیر داخلی `SOCKS5 127.0.0.1:18089` در Xray
3. دریافت مستقل کانال‌های رتبه اول و دوم از `t.me/s`
4. ذخیره اتمیک نامزدهای خام
5. قطع کامل اتصال اولیه
6. تست سریال و واقعی کانفیگ‌ها با Xray
7. جایگزینی تنها منبع ثابت `SUB`

## English

RC13 repairs the Android Telegram transport. The application package is intentionally excluded from its own `VpnService` to avoid a core routing loop, so previous scanner HTTP calls could leave through the device's physical IPv6 connection instead of the verified Xray outbound.

| Area | Change |
|---|---|
| Android route | A loopback SOCKS5 inbound is created inside the active Xray instance and every scanner `t.me` request uses it explicitly |
| DNS | `t.me` hostname resolution occurs through the proxy path rather than the phone's physical DNS/IPv6 route |
| Collector algorithm | Each channel is fetched independently, matching DicodeConfigChecker behavior; failures in the first channels no longer abort the complete scan |
| Source | Canonical `https://t.me/s/<channel>` only; no active `telegram.me` fallback |
| Performance | Eight bounded workers, connection reuse, cancellable calls and target-based early completion |
| Progress | 70% completed-channel work plus 30% candidate-target progress, published monotonically |
| Output | Raw candidates are atomically persisted before disconnect, then isolated real Xray probes replace the single `SUB` source |
