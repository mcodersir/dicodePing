# dicodePing v1.9.0-rc.9

## فارسی

نسخه RC9 مسیر اسکنر را به یک فرایند مرحله‌ای و قابل‌ردیابی تبدیل می‌کند: ابتدا VPN داخلی dicodePing متصل و اعتبارسنجی می‌شود، سپس فهرست کامل کانال‌های عمومی پروژه DicodeConfigChecker پیمایش می‌شود، کانفیگ‌های خام پیش از قطع اتصال روی دیسک نگه‌داری می‌شوند، VPN کاملاً متوقف می‌شود و در پایان هر کانفیگ با هسته Xray و درخواست واقعی HTTP سنجیده می‌شود. فقط نتایج سالم در منبع ثابت `SUB` ذخیره و جایگزین می‌شوند.

| بخش | تغییر RC9 |
|---|---|
| دریافت تلگرام | فهرست ۳۲۴ کانال عمومی همراه پروژه، اولویت‌بندی رتبه ۱ و ۲ و پردازش موازی محدودشده |
| سهم هر کانال | حداکثر ۸ کانفیگ برای کانال رتبه ۱ و ۹ کانفیگ برای کانال رتبه ۲ |
| مسیر شبکه | اتصال VPN پیش از دریافت؛ مسیر TUN به‌عنوان مسیر اصلی و SOCKS5 محلی به‌عنوان fallback محدود |
| ایمنی مرحله‌ای | ذخیره اتمیک `scanner-stage1-raw.txt` و metadata قبل از قطع VPN |
| تست واقعی | اجرای Xray، ساخت SOCKS موقت، درخواست HTTP واقعی، چند نمونه و مرتب‌سازی براساس median latency |
| ظرفیت | دریافت تا ۱۸۰ کاندید، تست تا ۱۶۰ کاندید و ذخیره حداکثر ۸۰ سرور سالم در دسکتاپ |
| Android | همان ترتیب دریافت، ذخیره مرحله اول، قطع VPN و تست Native؛ سقف ۶۰ نتیجه سالم |
| رابط کاربری | بازخورد فوری پس از شروع، لاگ‌های جداگانه اتصال/VPN، تلگرام و تست، و کارت‌های خواناتر سرورها |


### هسته‌های همراه نسخه

- Xray، Aether و WARP/Usque داخل خروجی همان پلتفرم قرار می‌گیرند و فایل Core جداگانه‌ای منتشر نمی‌شود.
- در Android، Aether و Usque به‌عنوان کد Native متعلق به APK در `nativeLibraryDir` اجرا می‌شوند؛ کپی و اجرای فایل از پوشه قابل‌نوشتن برنامه حذف شده است.
- گزینه VPN برنامه‌محور در تنظیمات Android به تب «مسیریابی» منتقل شده است.
- مجوز VPN مستقیماً از صفحه اسکنر درخواست می‌شود و پس از تأیید، اتصال اولیه بدون انتقال کاربر به خانه آغاز می‌شود.

### ترتیب اجرای اسکنر

1. انتخاب بهترین سرور منبع اصلی و روشن‌کردن VPN dicodePing.
2. دریافت کانفیگ از کانال‌های رتبه ۱ و رتبه ۲.
3. ذخیره کاندیدهای خام و گزارش مرحله اول.
4. قطع کامل VPN و هسته bootstrap.
5. تست واقعی کانفیگ‌ها روی شبکه مستقیم.
6. جایگزینی منبع ثابت `SUB` و نمایش نتایج در صفحه سرورها.

> دسترسی به پیش‌نمایش عمومی تلگرام و تعداد کانفیگ سالم به وضعیت شبکه، محتوای لحظه‌ای کانال‌ها و محدودیت‌های تلگرام وابسته است.

## English

RC9 turns the scanner into an explicit staged pipeline. dicodePing first connects and validates its own bootstrap VPN, crawls the full public-channel set supplied with DicodeConfigChecker, atomically persists raw candidates, completely stops the bootstrap VPN, and then measures each candidate through an isolated Xray process and a real HTTP request. Only verified results replace the single persistent `SUB` source.

| Area | RC9 change |
|---|---|
| Telegram collection | Bundled 324-channel public list, rank-aware ordering, and bounded parallel crawling |
| Per-channel limits | Up to 8 configs from each rank-1 channel and 9 from each rank-2 channel |
| Network route | dicodePing VPN before collection; verified TUN first with bounded local SOCKS5 fallback |
| Stage safety | Atomic raw candidate and metadata snapshot before bootstrap disconnect |
| Real verification | Xray process, temporary SOCKS listener, real HTTP request, repeated samples and median latency |
| Capacity | Up to 180 collected candidates, 160 probes, and 80 saved desktop results |
| Android | The same collect, persist, disconnect, native-probe sequence with up to 60 healthy results |
| UX | Immediate start feedback, separate VPN/Telegram/test logs, and clearer server cards |


### Cores bundled with each package

- Xray, Aether, and WARP/Usque ship inside each platform artifact; the release no longer publishes separate core archives.
- On Android, Aether and Usque run as APK-owned native code from `nativeLibraryDir`; copying executables into writable app storage has been removed.
- Android per-app VPN controls now live under the Routing settings tab.
- The scanner requests VPN consent in place and starts its own bootstrap connection after approval instead of redirecting the user to Home.

### Scanner sequence

1. Select a primary-source server and start the dicodePing VPN.
2. Crawl rank-1 and rank-2 Telegram channels.
3. Persist the stage-one raw candidates and metadata.
4. Fully stop the bootstrap VPN and process.
5. Probe candidates on the direct network.
6. Replace the single `SUB` source and refresh the server list.

> Telegram preview reachability and the number of healthy configurations depend on the current network, live channel contents, and Telegram-side restrictions.
