# dicodePing v1.7.0-rc.4

این نسخه یک pre-release کامل برای ویندوز، لینوکس و اندروید است و تمرکز آن
روی اسکن واقعی، پایداری اتصال، مصرف هوشمند منابع و رابط responsive است.

## هسته تطبیقی dicodePing + Xray

dicodePing در شروع اجرا تعداد هسته‌های CPU و حافظه قابل استفاده را می‌خواند
و یک پروفایل immutable می‌سازد. این پروفایل تعداد crawler، DNS resolver،
ping، Xray probe، retry worker، ظرفیت صف داخلی و `policy.bufferSize` رسمی
Xray را تنظیم می‌کند. حدها برای روترهای تک‌هسته‌ای/کم‌حافظه محدود و برای
سیستم‌های قوی تا سقف‌های کنترل‌شده افزایش می‌یابند.

نسخه Xray دسکتاپ روی `v26.7.11` pin شده و archive رسمی به‌همراه digest رسمی
بررسی می‌شود. تنظیمات اتصال از فیلدهای رسمی `sockopt` شامل Happy Eyeballs،
TCP keepalive و TCP user timeout استفاده می‌کند. اندروید همچنان از
AndroidLibXrayLite نسخه pin‌شده و SHA-256 کنترل‌شده استفاده می‌کند.

## بهبودهای عملی پایداری و Memory Leak

1. **حذف thread نشت‌کننده اسکنر:** threadی که پس از هر اسکن موفق تا ابد روی
   `Event.wait()` باقی می‌ماند حذف شد و همان cancellation event مالک اسکن است.
2. **صف محدود probe:** به‌جای ساخت Future برای تمام کانفیگ‌ها، حداکثر یک
   پنجره سه‌برابر concurrency در حافظه نگهداری و به‌تدریج refill می‌شود.
3. **لغو سراسری پردازش Xray:** توقف اسکن به probe فعال منتقل می‌شود؛ پردازش
   Xray terminate و در صورت لزوم process tree آن kill و فایل موقت پاک می‌شود.
4. **coalesce کردن cleanup دسکتاپ:** چند مسیر هم‌زمان Disconnect/monitor/exit
   فقط یک worker پاک‌سازی TUN می‌سازند و فایل log قبل از حذف بسته می‌شود.
5. **serialization هسته اندروید:** startهای متوالی با Mutex و generation
   محافظت می‌شوند؛ job قبلی cancel-and-join شده و CoreBridge پیش از جایگزینی
   controller قبلی را می‌بندد.
6. **مالکیت lifecycle اندروید:** scanner در `viewLifecycleOwner` اجرا می‌شود،
   پس خروج از صفحه crawl/import را cancel می‌کند و binding قدیمی نگه نمی‌ماند.
7. **بافر تطبیقی Xray:** `bufferSize` به‌جای مقدار ثابت، بر اساس memory class
   تعیین می‌شود تا درخواست‌های زیاد روی بردهای ضعیف باعث جهش RAM نشوند.

## اسکن، پینگ و انتخاب بهترین سرور

- اسکنر اندروید در صورت نیاز خودکار به بهترین bootstrap متصل می‌شود، کانال‌ها
  را crawl می‌کند، پیش از probe تونل bootstrap را واقعاً می‌بندد، نتایج را
  وارد source پایدار `scanner-auto` می‌کند، با Xray HTTP probe می‌سنجد و در
  پایان به بهترین نتیجه سالم وصل می‌شود.
- اسکنر دسکتاپ نیز crawl و probe را با concurrency تطبیقی و cancellation واقعی
  اجرا می‌کند.
- ping متصل دسکتاپ اکنون زمان HTTP واقعی داخل TUN است؛ ICMP فقط برای غربال
  اولیه سرورها باقی مانده است.
- انتخاب خودکار علاوه بر latency معتبر، سابقه failure، اتصال موفق اخیر،
  موقعیت معتبر و تنوع endpoint را لحاظ می‌کند. در خرابی یک سرور تا پنج
  کاندیدای سالم بعدی به‌صورت خودکار امتحان می‌شوند.

## رابط کاربری

- در دسکتاپ sidebar، hero، آمار، ابزارهای سرور، اکشن‌های scanner و ستون‌های
  جدول در عرض‌های کوچک reflow یا hide می‌شوند. اندازه حداقل به 680×480 کاهش
  یافته و اندازه اولیه با فضای واقعی نمایشگر محدود می‌شود.
- در هدر فارسی اندروید، متن بدون کادر به «رفع تحریم‌ها» تغییر کرده و سمت راست
  است؛ برند داخل کادر با متن `dicodeping` در سمت چپ قرار دارد.
- نتیجه اسکن اندروید دیگر نمایشی نیست و تعداد دریافت‌شده، ذخیره‌شده و سالم را
  از داده واقعی Repository نشان می‌دهد.

## Release validation

The Android scanner is compiled against the shared `ConnectionHost` contract, so
its automatic bootstrap, teardown, and best-server reconnect path are validated
by the signed release build as well as CodeQL.
