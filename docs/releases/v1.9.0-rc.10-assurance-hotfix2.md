# dicodePing 1.9.0 RC10 — Xray/Scanner Assurance Hotfix 2

This hotfix strengthens Android Xray startup, VPN lifecycle recovery and the scanner transaction.

## Verification contract

- The UI may report Connected only after the embedded Xray core is running and a real HTTP probe succeeds.
- A scanner run first verifies the embedded core, connects the bootstrap VPN, collects Telegram candidates, persists stage one atomically, disconnects the VPN, then runs serialized Xray HTTP probes.
- Native one-shot probes remain serialized because libgojni uses process-wide state.
- Telegram extraction is intentionally limited to VMess, VLESS, Trojan and Shadowsocks because those are the protocols this release can parse and execute end-to-end.
- Stale VPN intents are not replayed after Android recreates the service.
- No release can honestly guarantee every OEM/device/network combination without physical-device testing; failures are converted to explicit states instead of process crashes wherever the platform permits.
