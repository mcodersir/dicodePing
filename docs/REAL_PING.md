# سنجش واقعی مسیر

برای هر نمونه این توالی اجرا می‌شود:

1. اتصال به inbound محلی SOCKS مربوط به همان کانفیگ؛
2. دستور SOCKS5 CONNECT برای یک مقصد مستقل؛
3. TLS handshake با بررسی زنجیره و نام گواهی؛
4. درخواست HTTP و خواندن status/header؛
5. ثبت tunnel time، TLS time، first-byte و total time؛
6. تکرار روی مقصدهای متفاوت و محاسبهٔ median/jitter/loss.

قبولی TCP به IP سرور فقط ثابت می‌کند پورت باز است و قبولی ICMP حتی ممکن است مربوط به مسیر متفاوت باشد. DicodePing یک کانفیگ را فقط وقتی سالم می‌داند که درخواست end-to-end از outbound آن عبور کند.

امتیاز صرفاً برای مرتب‌سازی داخل همان اسکن است و SLA یا تضمین سرعت دانلود نیست. شرایط اپراتور، ساعت، مقصد و congestion نتیجه را تغییر می‌دهد.
