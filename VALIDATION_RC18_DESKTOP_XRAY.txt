dicodePing v1.9.0-rc.18 full desktop TUN validation
=====================================================

Validated in source/package preflight:
- 134 Python tests passed.
- Windows, Linux and macOS Xray startup uses a real TUN inbound.
- IPv4 and IPv6 default routes are configured with autoSystemRoutingTable.
- Xray outbound loop prevention uses autoOutboundsInterface, sendThrough and direct server host routes.
- Windows build requires and packages wintun.dll and requests UAC elevation.
- Linux relaunches through PolicyKit while preserving the user profile/session environment.
- macOS selects a valid unused utunN interface and requests native administrator authorization.
- A private SOCKS probe validates the selected Xray server before TUN route verification.
- A direct HTTP request with all OS proxy/PAC handlers disabled verifies full-device TUN routing.
- Xray startup never enables a new operating-system proxy configuration.
- Disconnect removes temporary routes, runtime files, Xray process state and the named TUN adapter.
- Android Gradle/source/project validation passed.
- 57 Android XML files and 271 localized strings validated.
- Quality Gate completed with 0 errors and 0 warnings.
- All GitHub Actions YAML files parsed successfully.

Environment limitation:
A signed release could not be connected on physical Windows, Linux and macOS
machines in this environment. GitHub Actions performs native packaging, while
final route/driver behavior still needs a real-machine smoke test.
