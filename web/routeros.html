روباه روی روتر MikroTik

کانتینر آزمایشی DicodePing روی شبکهٔ محلی یک پراکسی HTTP و SOCKS5 با نام کاربری و رمز ارائه می‌کند. هر دستگاهی که پراکسی را در تنظیمات خودش قرار دهد می‌تواند از روباه استفاده کند. این مسیر ترافیک TCP را حمل می‌کند و مسیر پیش‌فرض شبکه را تغییر نمی‌دهد.

۱. دستگاه و بسته را بررسی کنید

/system/resource/print
/system/package/print
/system/device-mode/print

بستهٔ container هم‌نسخه با RouterOS را نصب کنید. برای RouterOS روی ARM64 یا x86_64 شامل CHR، TAR هماهنگ با همان معماری را بگیرید. به دیسک خارجی و دسترسی فیزیکی برای تأیید Device Mode نیاز دارید. در صورت غیرفعال‌بودن Container فرمان زیر را اجرا کنید و طبق خروجی روتر، تغییر را با دسترسی فیزیکی تأیید کنید. روتر راه‌اندازی مجدد می‌شود.

/system/device-mode/update container=yes

۲. شبکهٔ کانتینر را بسازید

نمونه از 172.30.91.0/24 برای کانتینر، 192.168.88.0/24 برای LAN و disk1 برای دیسک استفاده می‌کند. مقادیر را با شبکهٔ خود تطبیق دهید. نام WAN باید فهرست رابط اینترنت روتر شما باشد. هنگام اعمال تغییرات از WinBox Safe Mode استفاده کنید.

/interface/bridge/add name=dicode-fox-bridge
/ip/address/add address=172.30.91.1/24 interface=dicode-fox-bridge comment=dicode-fox
/interface/veth/add name=dicode-fox-veth address=172.30.91.2/24 gateway=172.30.91.1
/interface/bridge/port/add bridge=dicode-fox-bridge interface=dicode-fox-veth
/ip/firewall/nat/add chain=srcnat src-address=172.30.91.0/24 out-interface-list=WAN action=masquerade comment=dicode-fox

در زنجیرهٔ forward فایروال، اتصال TCP به 172.30.91.2:10810 را فقط برای VLAN یا رابط LAN مورد اعتماد باز کنید. این محدودیت باید پیش از قواعد عمومی و FastTrack قرار بگیرد. این پورت را روی WAN منتشر نکنید.

فایل TAR را در Files روی دیسک روتر بگذارید. برای نسخهٔ CHR نام فایل را به DicodePing-5.0.9-routeros-x86_64.tar تغییر دهید.

/container/mounts/add list=dicode-fox-data src=disk1/dicode-fox-data dst=/data
/container/add file=disk1/DicodePing-5.0.9-routeros-arm64.tar interface=dicode-fox-veth root-dir=disk1/dicode-fox-root mountlists=dicode-fox-data logging=yes start-on-boot=no
/container/print

۳. وارد حساب Firefox شوید و اتصال را بگیرید

پس از آماده‌شدن ایمیج، شمارهٔ کانتینر را از خروجی /container/print بردارید. این مثال شمارهٔ صفر را به کار می‌برد.

/container/start 0
/container/shell 0
dicode-router login

ایمیل و رمز حساب Firefox، کشور و در صورت نیاز کد تأیید را در ترمینال تعاملی وارد کنید. برای پراکسی LAN نام کاربری و رمز جداگانه تعریف کنید. پوشهٔ نشست حساب و رمز پراکسی را خصوصی نگه دارید.

در دستگاه کلاینت، از پراکسی 172.30.91.2 روی پورت 10810 استفاده کنید. curl رمز پراکسی را جداگانه می‌پرسد. IP خروجی را با اجرای URL بدون پراکسی مقایسه کنید.

curl --proxy socks5h://172.30.91.2:10810 --proxy-user YOUR_PROXY_USER https://api.ipify.org

برای توقف آزمایش /container/stop 0 را اجرا کنید و پراکسی را از کلاینت‌ها بردارید. پس از تأیید اتصال می‌توانید start-on-boot=yes را برای همان کانتینر فعال کنید.

روباه در شبکهٔ Cisco

روی میزبان Linux داخل LAN سیسکو، TAR هماهنگ با معماری میزبان را در Docker بار کنید. در این مثال 192.168.88.20 آدرس میزبان Linux است. در ACL یا فایروال میزبان، پورت 10810 را به شبکهٔ مجاز محدود کنید.

docker load --input DicodePing-5.0.9-routeros-x86_64.tar
docker run -d --name dicode-fox --restart unless-stopped -p 192.168.88.20:10810:10810/tcp -v dicode-fox:/data dicodeping-router:5.0.9
docker exec -it dicode-fox dicode-router login
curl --proxy socks5h://192.168.88.20:10810 --proxy-user YOUR_PROXY_USER https://api.ipify.org

اجرای مستقیم IOS XE به مدل دستگاه و App Hosting وابسته است. این روش به میزبان Linux نیاز دارد. کانتینر آزمایشی فقط برای برنامه‌های سازگار با پراکسی است.
